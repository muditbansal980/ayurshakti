# Project task records

Break each user request into small, independently verifiable work items.
Write one Markdown file per completed work item under `tasks-completed/`.
Keep unfinished work under `tasks-in-progress/`; move it only when its stated
acceptance criteria pass. Use numbered descriptive filenames.

Each record includes the request, scope, explanation, changed files, validation,
limitations, and next steps. Never record credentials or claim unrun checks pass.
For this project, data-processing chunks and task breakdowns are different ideas.
